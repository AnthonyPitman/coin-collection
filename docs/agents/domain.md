# Domain docs

## Layout

This repo uses a single-context layout:
- GLOSSARY.md at the repo root.
- Architecture decision records in docs/adr/.

## Before exploring

Read GLOSSARY.md and any ADRs relevant to the work.

If these files do not exist, proceed silently. Domain modeling
creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the
gap for domain modeling.

## Decisions

When a proposal contradicts an ADR, identify the ADR and explain
why the decision should be reconsidered.
